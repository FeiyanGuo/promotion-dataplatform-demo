# 晋升数据中台 · 版本说明 v0.1

> 面向对象：HR 负责人 / IT / 安全合规
> 日期：2026-09-22

## 一句话结论

把"每次晋升数据都要总部 OD 手工整理、按人授权"的模式，升级为**按组织授权、BP 自助查询下载、全程留痕**的在线平台原型。BP 轮岗/离职不再造成数据断供，也不再有"找小F要数据"的瓶颈。

## 解决的核心问题

| 痛点 | 平台方案 |
|---|---|
| 晋升数据按年窗口下载、历史难拼接 | 长表自动合并为「员工×年度」数据表，每年只需追加当年数据 |
| BP 轮岗/离职后继任来要数据 | 权限挂在**组织**上（中心→部门两级），人换授权不动 |
| 手工匹配花名册、做透视表，易错耗时 | 上传花名册/晋升表自动转换，支持筛选、排序、一键导出 |
| 数据外发无管控 | 账号登录 + 服务端按权限强制过滤 + 全操作审计留痕 |

## 功能清单

**BP 侧（查询下载）**
- 进入页面自动加载本人权限范围内全部晋升数据
- 筛选栏（可折叠）：中心/部门树状多选、职级区间、逐年是否晋升、姓名/工号搜索，全部 AND 关系
- 全字段点击排序；所见即所得导出 Excel，另可切换"导出全量"
- 页面统计数字一律按本人权限范围实时计算

**OD 侧（管理后台）**
- 组织授权：架构图由花名册【中心】【部门】自动生成，「授权HRBP」字段内联配置、自动保存；中心授权自动覆盖下挂部门
- 授权配置导出/批量导入（xlsx，全量替换，先校验后写入，失败整体不落盘）
- 数据导入：晋升数据 / 花名册上传，支持"追加补数"（按主键去重）与"全量替换"，带模板下载与列校验
- 审计日志：登录、查询、导出、导入、权限变更全部留痕

## 权限模型（关键设计）

- 授权对象：中心、部门两级组织节点，存储在 BP 账号上
- 有效范围 = 中心授权展开的部门 ∪ 部门直授；**服务端强制过滤**，前端传参绕过无效
- 管理员（小F）通过白名单获得全权，不占组织授权
- 演示账号：`admin`（全量）、`bp_wang`（技术中心）、`bp_chen`（业务中心）、`bp_liu`（职能中心），密码 `admin123` / `bp123`

## 技术架构

- 前端：React 19 + TypeScript + Vite + Tailwind/shadcn（单页应用）
- 后端：Node.js + Express（与前端同端口部署），JSON 文件存储（原型级）
- 宽表引擎：按晋升生效时间自然年归集，同年多条取最早生效一条
- 启动：`npm run dev`（开发）/ `npm run build && npm start`（生产，端口 7100，strictPort）

## 当前边界（原型级，正式化前必须替换）

1. **密码明文存储** → 接公司 SSO（飞书/钉钉/AD）
2. **会话在内存**（服务重启即失效）→ Redis / 数据库会话
3. **JSON 文件存储**（无并发保护）→ SQLite / 公司数仓
4. 无下载水印、无异常行为告警
5. 演示数据为脱敏样例（230 人 / 130 条晋升 / 2023–2026），未接触真实生产数据

## 数据更新 SOP（每年）

1. 晋升系统下载当年长表 → 管理后台「追加补数」上传（重复上传自动去重，不会重复）
2. 下载最新花名册（含【中心】【部门】列）→ 「全量替换」上传
3. 架构图自动更新；新 BP 入职/轮岗在「组织授权」页调整即可

## 路线图

- 一期（本版）：自助查询下载、组织授权、数据导入、审计 ✅
- 二期：SSO 接入、数据库化、下载水印、异常告警
- 三期：权限申请自助审批、纳入调动/绩效等其他 HR 数据
